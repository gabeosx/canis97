<objective>
**As a** SiriusXM subscriber, **I want to** choose a nostalgic local appearance, **so that** the player feels personal while remaining declarative, bounded, accessible, and recoverable.

Deliver the production tracer from a native Player command through selected-appearance state and persistence to the existing compact renderer, then complete two bundled skins on that same contract.

Purpose: Prove the phase's hardest architectural constraint first: appearance may vary while controls, semantics, accessibility, playback authority, and fixed window policy remain app-owned.
Output: A closed appearance contract, one generalized selection path, atomic metadata-only persistence, two bundled skins, native fallback recovery, and compile/offline regression coverage.
</objective>

<interfaces>
- `CompactPlayerPresentation` is a renderer-independent `Sendable, Equatable` value. It carries semantic channel/playback/favorite/transport state and no behavior closure.
- `CompactPlayerAction` is the closed app-owned action vocabulary: previous, playPause, next, toggleFavorite, showLibrary, toggleAlwaysOnTop, retryPlayback, signInAgain, and refreshLibrary.
- `CompactPlayerView` currently accepts `presentation`, `onAction`, `isAlwaysOnTop`, and `onAlwaysOnTopChanged`; preserve these owners and add validated appearance as data, not as action authority.
- `NativeCompactPlayerStyle.fallback` fixes 400 x 288 content, semantic colors, 16-point padding, and 8-point section spacing; `CompactPlayerPresentation.transportControlSize` fixes transport controls at 32 points.
- `CompactListeningSlice` and `ListeningCommands` in `SiriusMacApp.swift` already share app-owned controller routes. The new `SkinAppearanceController` must have the same app-lifetime identity across both surfaces.
- `WindowLifecyclePolicy.defaultContentSize` returns exactly 400 x 288 for `.compact`; appearance data never enters this policy.
</interfaces>
