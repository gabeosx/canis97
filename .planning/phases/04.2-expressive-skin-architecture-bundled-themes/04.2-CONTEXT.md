# Phase 4.2: Expressive Skin Architecture & Bundled Themes - Context

**Gathered:** 2026-08-27 (assumptions mode)
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver genuinely transformative Winamp-inspired skinning for the compact player through a versioned declarative contract that can safely vary layout, layered artwork, chrome, typography, bounded drag regions, apparent window silhouette, and a small set of app-owned window sizes. Ship three complete original themes—Pixel Desk, Pocket Disc, and Aqua Vista—that materially differ in more than color while preserving native behavior, accessibility, package safety, and unconditional Native recovery.

This phase does not add song favorites or service playlist connections; local song favorites move to Phase 04.3. It also does not add executable skins, remote galleries or assets, arbitrary layout code, arbitrary font files, skin-authored AppKit policies, per-pixel click-through windows, library-window theming, or changes to authentication, playback, persistence, menus, or service integrations.

</domain>

<decisions>
## Implementation Decisions

### Versioned expressive skin contract

- **D-01:** Introduce an explicit new schema version that supersedes the Phase 04/04.1 prohibition on skin-selected compact-player layout, geometry, and silhouette only within the bounded authority defined here. Schema versions 1 and 2 must continue to render unchanged or pass through an explicit deterministic migration before selection. Unsupported or invalid documents fail closed. — **Reversibility:** costly — once packages use the new public schema, undoing it requires package migration and compatibility handling.
- **D-02:** The expressive schema is a closed declarative vocabulary, not a general-purpose layout language. It may reference app-defined semantic slots, finite layout and silhouette variants, bounded layered decorations, typography tokens, and validated drag regions; it cannot contain code, scripts, constraints, selectors, arbitrary window flags, networking, remote URLs, or arbitrary file access.
- **D-03:** Every candidate must validate required semantic controls, frame bounds, non-overlap rules, minimum usable targets, text capacity, decoration budgets, asset references, and at least one usable drag region before it can render or become the durable selection. Invalid candidates leave the previous valid selection untouched.
- **D-04:** Bundled and imported themes use the same catalog, decoder, validator, semantic renderer, and recovery rules. The three bundled themes must prove the public contract rather than relying on privileged theme-specific renderers.

### Native behavior and accessibility sovereignty

- **D-05:** A skin arranges only a closed set of app-defined semantic controls and regions. Sirius owns the SwiftUI controls, action routing, enabled state, accessibility labels and values, keyboard behavior, focus order, VoiceOver announcements, playback truth, and recovery behavior. Skins cannot add, remove, rename, or redefine player actions. — **Reversibility:** costly — allowing packages to own semantics would couple public package data to behavior and require a coordinated schema and renderer migration to undo.
- **D-06:** Preserve the established 32×32 transport hit targets and readable app-owned focus/state indicators. Focus halos must remain visible inside the silhouette; decorative layers and drag overlays are hidden from accessibility; visual rearrangement must not destabilize semantic source order.
- **D-07:** Reduce Motion disables theme resize flourishes, bounce, parallax, and other nonessential movement. Theme changes may be instantaneous or use a restrained app-owned crossfade, and no theme may require animation to communicate state.

### Window shape, size, and restoration

- **D-08:** Expressive themes create an apparent nonrectangular silhouette inside a transparent rectangular `NSWindow`; Phase 04.2 does not promise arbitrary per-pixel click-through holes or a truly nonrectangular native event region. Retain a titled, key-capable window with narrow AppKit configuration instead of adopting a borderless window role.
- **D-09:** Compact-player sizes come from a small app-owned finite set selected by validated theme tokens. Native and legacy v1/v2 appearances remain 400×288. Imported skins cannot request arbitrary dimensions, minimums, maximums, or resize behavior.
- **D-10:** Theme-size changes are controller-owned and atomic: preserve the visible top-left position where possible, apply content minimum/maximum size together, choose the appropriate screen, clamp the complete frame into `NSScreen.visibleFrame`, persist a versioned compact position, and fall back to Native for invalid restoration state.
- **D-11:** Declarative drag regions are bounded, remain behind controls, cannot overlap interactive frames, and must leave all controls normally clickable. The application owns the actual drag gesture and window movement.

### Original bundled themes and asset provenance

- **D-12:** Ship three complete public themes named **Pixel Desk**, **Pocket Disc**, and **Aqua Vista**. Their shared inspiration is intentionally recognizable, but their names, artwork, icons, type treatment, layout details, and ornamentation must be original rather than copied from Apple, Sony, Microsoft, Winamp, or other products.
- **D-13:** Pixel Desk uses an original late-1990s desktop grammar: warm beige/gray surfaces, crisp pixel ornaments, bevels, dithering, and compact utility-window character. It must not reproduce Apple/Finder/Platinum assets, marks, system icons, or proprietary classic Mac fonts.
- **D-14:** Pocket Disc uses an original portable audio-device grammar: brushed or molded hardware surfaces, a segmented information display, asymmetric controls, labels, screws, and tactile details. It must not use Sony, MiniDisc, MD, Walkman, ATRAC, model-number, or product-copy assets or marks.
- **D-15:** Aqua Vista uses an original optimistic nature-and-technology grammar: sky, foliage, water, translucent glass, bubbles, highlights, and dimensional controls. It must not reproduce Microsoft/Windows marks, wallpapers, icons, or proprietary assets.
- **D-16:** Theme resources require explicit provenance. Typography uses system font tokens and, only if needed, a small reviewed set of app-bundled fonts with redistribution-compatible licenses such as OFL; imported packages cannot carry font binaries. Do not bundle Apple system font files, classic Mac fonts, Frutiger, or another commercial/vendor font without an independently verified license.

### Recovery and validation

- **D-17:** Native remains permanent, package-independent, non-removable, and reachable from an app-owned menu even if a selected skin cannot decode, validate, render, or fit on the active screens. Rendering failure restores Native and reports the recovery truthfully.
- **D-18:** Preserve archive, path, symlink, entry-count, byte, image-dimension, decode, and processing budgets from the existing importer. The expanded visual vocabulary must not broaden package access to secrets, URLs, executable behavior, menus, authentication, playback, persistence, or accessibility strings.
- **D-19:** Completion requires offline structural tests plus deliberate visual and accessibility review of Native, legacy v1/v2 packages, all three new themes, populated/empty/error player states, keyboard-only use, VoiceOver order and labels, focus visibility, contrast, target sizes, Reduce Motion, theme-size transitions, restoration, and failure recovery. App launch, app-hosted tests, and UI automation remain blocked until the repository's separate safety review authorizes them.

### Superseded upstream decisions

- **D-20:** Phase 04 `D-03` and Phase 04.1 `D-09` remain authoritative for Native and legacy packages but are superseded for validated new-schema themes where they require a universal 400×288 size or prohibit all app-defined layout authority. Phase 04 `D-01`, `D-02`, `D-12`–`D-16` and Phase 04.1 `D-08`–`D-11` remain authoritative wherever this context does not explicitly narrow or replace them.

### the agent's Discretion

- Choose the exact finite size values beyond legacy 400×288, schema field names, semantic-slot names, silhouette and layout variant names, asset-layer limits, and deterministic v1/v2 compatibility implementation within the locked bounds.
- Choose the original art direction details, surface materials, ornaments, safe public copy, reviewed font tokens or OFL font choices, shadows, and restrained transition treatment for each bundled theme.
- Choose the exact AppKit bridge mechanics for transparent content, titlebar treatment, traffic-light visibility, system shadows, shadow invalidation, screen selection, clamping, and frame migration while retaining normal key/main-window behavior and Native recovery.

</decisions>

## Existing Code Insights

### Reusable Assets

- `SkinAppearanceCatalog`, `ValidatedSkinAppearance`, and `.native`: extend the single trusted catalog/validation/recovery path instead of adding theme-specific renderers.
- `CompactPlayerPresentation` and `CompactPlayerAction`: retain the existing semantic boundary and action ownership while a new layout host places app-created controls into validated slots.
- `CompactWindowController`, `WindowLifecyclePolicy`, `WindowFrameRestoration`, and `WindowFrameMigration`: extend the narrow AppKit seam for finite theme sizes, transparent chrome, clamping, and migrated position storage.
- `SkinPackagePolicy` and `SkinPackageImporter`: preserve hostile-input budgets and durable-save-first selection behavior while adding schema-v3 resources.
- Signal Glow and Tape Deck: compatibility fixtures for legacy schema rendering after the new contract lands.

### Established Patterns

- Appearance input is strictly decoded, finite, local, and non-executable; unknown keys and unsupported schema versions fail closed.
- The app projects validated semantic listening state into native SwiftUI controls; appearance values never execute actions or supply accessibility text.
- Selection changes only after full validation and managed promotion, while render-time asset failure restores the complete static Native appearance.
- Window behavior is isolated in a role-scoped AppKit adapter rather than spread through player views.

### Integration Points

- Extend manifest decoding and validation in `SkinAppearance.swift`, package policy/import in the skin subsystem, and bundled-resource registration in the existing appearance catalog.
- Refactor `CompactPlayerView` into an app-owned semantic control registry/layout host whose placement is driven only by validated schema-v3 values.
- Feed validated finite size/silhouette policy from selection state into `CompactWindowController` without allowing manifests to touch raw `NSWindow` policy.
- Keep `SiriusMacApp` as the composition root and owner of menu-based Native recovery.
- Expand static/offline tests around schema compatibility, hostile layouts, semantic-control preservation, window math, accessibility, and bundled-theme completeness.

</code_context>

<specifics>
## Specific Ideas

- The user explicitly rejected a color-only or lightly decorated treatment as “extremely boring” and wants meaningful Winamp-style nostalgia through art, different window silhouettes, chrome, typography, and control arrangement.
- Pixel Desk should evoke macOS 8-era compact utility windows without copying Apple assets or publicly using Apple naming.
- Pocket Disc should evoke the delight and tactile density of a MiniDisc player without using Sony or MiniDisc product identity.
- Aqua Vista should embrace the full optimistic, glossy, nature-and-technology energy associated with Frutiger Aero rather than merely borrowing its palette.
- The three themes should feel like three different physical or desktop objects built on one safe native player, not three recolors of the same card stack.

</specifics>

<deferred>
## Deferred Ideas

- Local song favorites for later manual addition to a user's preferred music service — Phase 04.3.
- Spotify, Apple Music, or other external authentication, matching, playlist creation, and playlist-write APIs — outside Phase 04.3 and the current roadmap.
- Arbitrary per-pixel click-through window regions, skin-authored raw `NSWindow` flags, executable/scripted skins, networking, remote galleries or assets, arbitrary font binaries, and animated skin runtimes — outside Phase 04.2.
- Extending expressive themes to the library, authentication, settings, or other app windows — future phase unless separately scoped.
- Direct import of classic Winamp, macOS, MiniDisc, Windows, or other vendor skin/assets/formats — intentionally unsupported.

</deferred>
