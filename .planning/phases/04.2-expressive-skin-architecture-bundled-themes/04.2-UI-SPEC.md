# Phase 04.2 — UI Design Contract

> Visual and interaction contract for the expressive compact-player themes. Generated by gsd-ui-researcher and approved by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — native SwiftUI views with the existing narrow AppKit compact-window controller |
| Preset | not applicable; this is a current-macOS SwiftUI app, not a React/Vite/Next.js project |
| Component library | Apple SwiftUI and AppKit only |
| Icon library | SF Symbols for app-owned semantic controls; original bundled raster/vector decoration only |
| Font | System SF Pro / SF Mono via validated system font tokens; no imported skin font binaries |

Existing `CompactPlayerView`, `CompactPlayerPresentation`, and `CompactWindowController` remain the source of semantic actions, accessibility, and window behavior. Schema-v3 values only select validated visual/layout tokens. No third-party component registry is used.

## Spacing Scale

Declared layout values (all measurements in points and multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Label-to-icon gap; compact interior inset |
| sm | 8px | Default slot gap; transport-button gap |
| md | 16px | Default player interior padding; metadata-region inset |
| lg | 24px | Major region separation |
| xl | 32px | Minimum semantic transport target; compact control rail height |
| 2xl | 48px | Minimum artwork/display well dimension |
| 3xl | 64px | Large artwork/display well dimension |

Exceptions: one-pixel and two-pixel strokes, dither cells, screws, and other noninteractive ornament may use 1px or 2px measurements. They must not affect semantic-control frames, focus halos, drag regions, or hit testing. Theme size and all semantic-control frames remain multiples of 4.

## Typography

Only these sizes and weights may be selected by schema-v3 typography tokens. The app chooses the actual SwiftUI font, contrast, Dynamic Type behavior, and accessibility text.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | regular (400) | 1.5 |
| Label | 12px | regular (400) | 1.5 |
| Heading | 18px | semibold (600) | 1.2 |
| Display | 20px | semibold (600) | 1.2 |

Typography variants are finite: `systemRounded`, `systemMonospaced`, and `systemDefault`. Pixel Desk uses `systemMonospaced` for status/display treatment; Pocket Disc uses `systemMonospaced` for its segmented information display; Aqua Vista uses `systemRounded` for channel identity and `systemDefault` elsewhere. These are style treatments, not skin-supplied font files. Metadata remains readable at 14px or larger; no decorative type replaces semantic text.

## Color

The 60/30/10 split describes visual hierarchy, not a requirement to count pixels. Each bundled theme uses its listed original validated palette; imported schema-v3 packages can supply only the same named semantic color roles and must pass existing contrast/readability validation.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Pixel Desk `#C8C2AF`; Pocket Disc `#3E4641`; Aqua Vista `#C9EFF8` | Outer compact canvas, primary hardware/chrome planes |
| Secondary (30%) | Pixel Desk `#8A8E83`; Pocket Disc `#202825`; Aqua Vista `#78C4E3` | Information/display wells, control rails, inset panels |
| Accent (10%) | Pixel Desk `#304D92`; Pocket Disc `#A6E15A`; Aqua Vista `#198D74` | Selected favorite, enabled transport emphasis, selected appearance indicator, keyboard-focus ring, and active status only |
| Destructive | Pixel Desk `#A63A32`; Pocket Disc `#D85A48`; Aqua Vista `#C74654` | Appearance-removal confirmation and recovery/error status only |

Accent reserved for: the selected/favorited state, enabled primary Play/Pause state, active playback indicator, selected appearance checkmark, and the visible app-owned focus ring. Disabled controls, ornamental artwork, informational copy, and noninteractive drag regions do not use the accent.

Theme-specific materials: Pixel Desk is warm beige/gray with pixel bevels and restrained dithering; Pocket Disc is dark molded/brushed hardware with a green segmented display; Aqua Vista is sky/water/glass with foliage highlights and bubbles. All artwork, ornaments, control silhouettes, and names are original. Do not use Apple/Finder/Platinum, Sony/MiniDisc/Walkman, Microsoft/Windows, Winamp, or other vendor marks, proprietary artwork, or distinctive system icons.

## Compact Player Visual and Interaction Contract

### Approved theme catalog

| Appearance | Layout variant | Apparent silhouette | Fixed content size | Required visual distinction |
|------------|----------------|---------------------|--------------------|-----------------------------|
| Native and schema-v1/v2 appearances | `legacyStack` | `nativeRect` | 400 × 288 | Preserve current rendering and geometry unchanged, or use deterministic migration that produces this exact result. |
| Pixel Desk | `desktopUtility` | `pixelNotched` | 432 × 304 | Warm desktop utility object: square-ish bevels, dither/pixel ornament, compact title/display strip, and a horizontal control rail. |
| Pocket Disc | `discConsole` | `discPod` | 384 × 320 | Tall portable-device object: segmented information display, circular/offset control cluster, tactile labels/screws, and asymmetric artwork well. |
| Aqua Vista | `aquaPod` | `bubbleCapsule` | 448 × 304 | Wide translucent nature-tech object: layered sky/water/foliage art, glossy dimensional controls, bubbles, and a broad information panel. |

The apparent silhouette is drawn inside a transparent rectangular `NSWindow`. It never creates transparent click-through holes, changes the window role, makes the window borderless, controls traffic lights, selects arbitrary sizes, or supplies raw `NSWindow` flags. The compact window remains titled, key-capable, nonresizable, and application-owned.

### Closed semantic slots and source order

Schema-v3 may position only these app-created regions: `artwork`, `channelIdentity`, `metadata`, `favorite`, `status`, `transport`, `library`, and `overflowMenu`. It may select one of the four layout variants above; it cannot define a new slot, hide a slot, create an action, rename an action, provide accessibility strings, or change enabled state.

Visual placement can differ by variant, but SwiftUI source order, keyboard order, and VoiceOver order are fixed: compact player group; artwork; channel identity; current program; artist; playback status/recovery; favorite; Previous; Play/Pause; Next; Show Library; Always on Top; Sign Out. Decorative layers and drag regions are `.accessibilityHidden(true)` and never receive focus.

All app-owned control identifiers and labels remain unchanged, including `compact.favorite`, `compact.status`, `compact.transport.previous`, `compact.transport.play-pause`, `compact.transport.next`, `compact.show-library`, `compact.always-on-top`, and `compact.sign-out`.

### Layout validation and interaction rules

- Every required slot has exactly one non-overlapping semantic-control frame wholly inside the selected content size. A frame may visually overlap a decorative image only when the decoration is behind it and has hit testing disabled.
- Previous, Play/Pause, Next, favorite, Show Library, and overflow controls retain at least a 32 × 32pt hit target. The existing minimum is a floor, not an ornamental measurement.
- App-owned focus halos stay fully visible inside the apparent silhouette with a 4pt clear inset. A skin cannot obscure, recolor below contrast, or replace focus/state indicators.
- Metadata is restricted to one visible line each for title/program and artist. Channel identity is one line. Text that exceeds its validated slot pauses, then scrolls horizontally inside a clipped app-owned marquee; Reduce Motion uses tail ellipsis. Help and VoiceOver always expose the complete app-authored value.
- Schema-v3 permits at most six local decorative asset references: one backdrop, one chrome frame, one metadata/display plate, and up to three ornaments. They render behind semantic content, are noninteractive, and remain subject to the existing path, archive, image, byte, and decode budgets.
- A valid layout contains at least one app-owned draggable rectangle of at least 80 × 20pt. Drag rectangles are behind all controls, do not overlap interactive frames, have no accessibility element, and only invoke the application's window-drag gesture.
- Input validation rejects negative or out-of-bounds frames, non-4pt semantic measurements, overlapping interactive frames, absent required slots, targets under 32pt, insufficient text capacity, unsupported layout/silhouette/type tokens, inaccessible focus inset, an absent drag rectangle, excess layers, or unresolvable assets. Selection is atomic: retain the previous valid appearance on rejection.

### Window transition and recovery

- Native and legacy appearance selection always returns to 400 × 288pt. Pixel Desk, Pocket Disc, and Aqua Vista select only their approved sizes above.
- On a valid theme-size change, the controller preserves the visible top-left origin where possible, applies the content minimum and maximum together, selects the screen containing that origin, clamps the complete window frame to `NSScreen.visibleFrame`, then persists a versioned compact origin. It centers only when no valid origin can be restored.
- Invalid, off-screen, or incompatible restoration state selects Native at 400 × 288pt; it never applies a skin-provided arbitrary frame.
- A decoration decode/render failure immediately selects Native, restores normal Native chrome/size, and makes recovery status available. The Player menu's Native recovery route is always available, including when the selected package cannot decode, validate, render, or fit.

### Motion

Theme selection may use one app-owned 150ms opacity crossfade with no position interpolation, scale, bounce, parallax, autoplay, or skin-authored timing. The only continuous content motion is the app-owned bounded-text marquee, which pauses before moving and is disabled by Reduce Motion. With Reduce Motion enabled, changes and size transitions are immediate. State, focus, playback, and recovery must remain understandable with no animation.

## Copywriting Contract

All product copy is app-owned; packages supply neither visible semantic text nor accessibility text.

| Element | Copy |
|---------|------|
| Primary CTA | `Select Appearance` |
| Empty state heading | `Nothing Playing` |
| Empty state body | `Choose a channel in the Library to start listening.` |
| Appearance-list empty state | `No imported appearances yet.` followed by `Import a local .siriusskin package to add one.` |
| Loading state | `Loading playback` |
| Playback error state | `Playback couldn’t start.` followed by the existing app-owned recovery action: `Try Again`, `Sign In Again`, or `Refresh Library`. |
| Appearance recovery error | `This appearance is unavailable. Native appearance has been restored.` |
| Import/selection error | `This appearance couldn’t be used. Choose another package or select Native.` |
| Destructive confirmation | `Remove Appearance?` — `Remove {appearance name} from this Mac? Native and bundled appearances cannot be removed.` Buttons: `Remove {appearance name}` and `Keep {appearance name}`. |

Do not call a theme a “skin” in primary subscriber-facing selection copy; use “appearance.” Names appear exactly as `Pixel Desk`, `Pocket Disc`, and `Aqua Vista` without vendor, product, or retro-platform attribution.

## UI Considerations

Probe coverage: **29 applicable, 29 closed, 0 unresolved** — 21 explicit contracts, 4 visual-test backstops, and 4 reasoned dismissals.

| ID | Surface | Confirmed element kinds |

| E4 | Appearance import and removal flow | `form`, `interactive-control` |
| E5 | Theme chrome, decoration, and fixed layout | `static-content` |
| E6 | Native recovery routes | `nav`, `interactive-control` |

| Element | Category | Status | Resolution / Reason |
|---------|----------|--------|---------------------|
| E1 | empty | `resolved` / `explicit` | Without a confirmed channel, use the compact-player empty-state rows in the Copywriting Contract, keep Show Library available, and retain no stale media content. |
| E1 | loading | `resolved` / `explicit` | While playback is pending, use the playback-loading row in the Copywriting Contract; confirmed identity or artwork may remain visible while unavailable transport is disabled. |
| E1 | error | `resolved` / `explicit` | Use the playback-error or appearance-recovery rows in the Copywriting Contract and expose only the mapped app-owned recovery action; appearance failure restores Native. |
| E1 | populated | `resolved` / `explicit` | A confirmed channel renders all eight required semantic slots in the selected validated layout with app-owned content and actions. |
| E1 | overflow | `resolved` / `backstop` | `{ statement: "Verify every bundled theme in populated, empty, loading, and error states; no required text, control, focus halo, or recovery copy may clip outside the approved compact size.", verification: backstop }` |
| E1 | long-text | `resolved` / `backstop` | `{ statement: "Verify long Unicode channel, program, and artist values: each value stays inside its one-line slot, pauses and scrolls when it overflows, uses tail ellipsis with Reduce Motion, and remains complete in Help and VoiceOver.", verification: backstop }` |
| E2 | loading | `resolved` / `explicit` | During in-flight playback or appearance work, controls that cannot act are disabled rather than presented as available; focus order and labels remain stable. |
| E2 | error | `resolved` / `explicit` | Control failures preserve the prior valid state and expose only the mapped app-owned retry, reauthentication, refresh, or Native recovery action. |
| E2 | overflow | `resolved` / `explicit` | Every required control retains one non-overlapping frame of at least 32 × 32pt inside the approved size; less-frequent commands remain in the app-owned overflow menu and cannot be hidden by a theme. |
| E2 | long-text | `resolved` / `explicit` | App-owned control names and accessibility labels remain unchanged; visual labels may tail-ellipsize only where VoiceOver and Help retain the complete action name. |
| E3 | empty | `resolved` / `explicit` | Retain Native and Bundled sections and use the appearance-list empty-state rows in the Copywriting Contract when no imported appearance exists. |
| E3 | loading | `dismissed` | The local appearance catalog is synchronously available; import progress belongs to E4 rather than the list collection. |
| E3 | error | `resolved` / `explicit` | An invalid or unreadable imported appearance is not inserted or selected; retain the previous valid selection and use the app-owned import or selection error. |
| E3 | populated | `resolved` / `explicit` | The native `List` shows separate Native, Bundled, and Imported sections, one selectable row per validated appearance, and an app-owned selected-state indicator. |
| E3 | partial | `resolved` / `explicit` | Native and bundled appearances remain usable when Imported is empty or contains rejected packages; no partially validated row is shown. |
| E3 | overflow | `resolved` / `explicit` | The native `List` scrolls inside its container; section identity and selected state remain visible, and every row stays keyboard- and VoiceOver-reachable. |
| E3 | zero-one-many | `resolved` / `explicit` | Zero imported rows uses the documented empty copy; one renders one selectable row; many render individually selectable and removable rows with native scrolling and unchanged spacing. |
| E3 | long-text | `resolved` / `explicit` | Validated display names are capped at 64 characters; rows tail-ellipsize visually while the accessible row label exposes the complete validated name. |
| E4 | empty | `dismissed` | The picker/import action has no persistent unfilled form: idle is the enabled Select Appearance action, while an empty imported catalog is covered by E3. |
| E4 | loading | `resolved` / `explicit` | While importing, disable competing import and removal actions, show the labelled progress indicator, and keep Cancel Import available. |
| E4 | error | `resolved` / `explicit` | Rejection, unsupported schema, cancellation, selection failure, and removal failure use the corresponding app-owned copy; the previous valid appearance remains selected. |
| E4 | partial | `dismissed` | Import and selection are atomic: a package is fully validated and installed or absent, so no partially imported or half-applied form state may render. |
| E4 | long-text | `resolved` / `explicit` | Appearance names remain within the 64-character validation cap; destructive copy and buttons preserve the complete accessible name even if a visual label tail-ellipsizes. |
| E5 | overflow | `resolved` / `backstop` | `{ statement: "Verify Pixel Desk, Pocket Disc, and Aqua Vista at their fixed sizes across populated, empty, loading, and error states; decoration, drag regions, and focus clearance must never clip or cover semantic content.", verification: backstop }` |
| E5 | long-text | `resolved` / `backstop` | `{ statement: "Verify long Unicode metadata in every bundled silhouette: bounded player text scrolls without crossing its painted display, Reduce Motion tail-ellipsizes, and complete accessible values are preserved.", verification: backstop }` |
| E6 | loading | `dismissed` | Native recovery routes are local and always available; any in-flight retry progress belongs to E1 or E4 rather than recovery navigation. |
| E6 | error | `resolved` / `explicit` | When an appearance cannot validate, decode, render, restore, or fit, immediately select Native, restore Native size and chrome, show the documented recovery status, and keep the Player-menu Native route available. |
| E6 | overflow | `resolved` / `explicit` | Recovery remains reachable through the native Player menu and app-owned compact overflow menu regardless of theme geometry; no appearance may hide, replace, or move it outside app-owned navigation. |
| E6 | long-text | `resolved` / `explicit` | Recovery labels and messages are app-owned; fixed action names remain fully accessible, and recovery status must fit validated text capacity or the appearance is rejected before selection. |
