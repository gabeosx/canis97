<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WebKit cookie → volatile credential | Only an exact Secure issuer cookie may become opaque credential material. |
| App-owned website session → cleanup result | Exact token evidence and bulk nonpersistent-store retirement reduce browser state to a semantic success/failure only. |
| Rotated website session → SwiftUI/AppKit host | The fresh WebView must replace the retired visual/runtime instance before reuse. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-15-01 | Spoofing / Elevation of Privilege | token-cookie issuer predicate | high | mitigate | Require Secure plus exact apex/www allowlist, preserve name/path/expiry checks, and test insecure/unapproved/lookalike negatives. |
| T-01-15-02 | Information Disclosure | website-session retirement | high | mitigate | Use bulk removal and object replacement on the bridge-owned nonpersistent store; never enumerate/export unrelated values. |
| T-01-15-03 | Tampering | extraction/cleanup policy parity | high | mitigate | Keep one policy implementation and assert both bridge paths call it; success also requires a clean rescan. |
| T-01-15-04 | Repudiation | cleanup-complete outcome | high | mitigate | Aggregate exact rescan plus retirement result and test every partial-failure combination. |
| T-01-15-05 | Denial of Service | WebView rotation | medium | mitigate | Stop/release one old WebView, create one fresh session per explicit cleanup, and perform no background retry. |
</threat_model>
