## Phase Goal

**As a** SiriusXM subscriber, **I want to** use a cohesive native macOS player and library, **so that** one shared playback session continues correctly across app and system control surfaces.

<objective>
Add one local, secret-safe library store to the proven session and deliver shared favorites plus ordered confirmed-listen recents.

Purpose: Favorites and recents become useful across every surface without letting local convenience state become a credential, resource, or provider-data side channel.
Output: SwiftData-backed allow-listed records, an observable facade, UI/controller wiring, and deterministic persistence tests.

Decision coverage: D-09, D-10, and D-11 are implemented exactly; LIBR-01 idempotency/concurrency, LIBR-02 adjacency/empty/ordering, and LIBR-03 idempotency/concurrency fallback edges are explicitly resolved here.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Semantic client/channel → SwiftData | Provider-derived semantic presentation values cross into durable local storage. |
| Confirmed playback → listening history | A runtime transition becomes local persistent behavior. |
| UI commands → ModelContext | Concurrent favorite/clear actions mutate one store. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information Disclosure | LibraryStore SwiftData models | high | mitigate | Store an enumerated scalar allow-list; reflection/source tests reject credential, token, cookie, URL/resource, artwork, raw client, metadata payload, and diagnostic fields. |
| T-03-02 | Elevation of Privilege | Recent/favorite channel snapshots | high | mitigate | Stored records remain presentation-only; no persisted record is accepted as tune authorization and all later tuning enters the coordinator. |
| T-03-03 | Denial of Service | confirmation observer and ModelContext | high | mitigate | One main-actor store, transition dedupe, desired-state favorites, a hard 50-record cap, and idempotent clear prevent duplicate/unbounded work. |
| T-03-04 | Tampering | malformed or duplicate local records | high | mitigate | Validate required stable IDs, collapse duplicates deterministically, ignore/reject malformed records, and normalize ranks before publishing. |
