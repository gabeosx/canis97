## Phase Goal

**As a** SiriusXM subscriber, **I want to** use a cohesive native macOS player and library, **so that** one shared playback session continues correctly across app and system control surfaces.

<objective>
Prove the Phase 3 architecture with one production-quality vertical tracer: authenticate once, compose one listening session at application lifetime, show it through distinct compact and library scene roots, issue one tune through the shared coordinator, and render only its confirmed state on both surfaces.

Purpose: The hardest phase constraint is singular playback ownership. Proving it before persistence, queue, renderer, window, and MediaPlayer expansion prevents every later surface from acquiring accidental ownership.
Output: An app-owned session controller, two singleton scene roots using it, confirmed-state metadata fan-out, and executable invariant tests.

Decision coverage: D-01, D-02, and D-08 are implemented here; D-07's renderer boundary is expanded in Plan 03-04 without changing this ownership seam.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SwiftUI scenes → app session | Independently created scene content must not acquire playback or authentication ownership. |
| Browse intent → playback authority | Untrusted/stale selection is semantic input; the existing coordinator/client remains the tune authority. |
| Confirmed playback → presentation | Only observed coordinator state may fan out to metadata and UI. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information Disclosure | ListeningSessionController surface projections | high | mitigate | Expose semantic channel/playback values and closures only; tests assert no credential, session, transport, resource, or URL type crosses into a surface. |
| T-03-02 | Elevation of Privilege | browse selection and tune route | high | mitigate | Selection performs no playback; every tune still enters the existing coordinator and client authorization path. |
| T-03-03 | Denial of Service | window composition and playback owner | high | mitigate | App-level singleton ownership plus construction-count tests prevent duplicate players and repeated scene work. |
| T-03-04 | Tampering | semantic presentation boundary | high | mitigate | Confirmed-state tests prevent view/scene intent from forging playing or metadata state; renderer expansion must consume this closed projection. |
</threat_model>
