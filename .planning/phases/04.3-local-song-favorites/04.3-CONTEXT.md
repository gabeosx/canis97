# Phase 04.3: Local Song Favorites - Context

**Gathered:** 2026-08-28 (assumptions mode)
**Status:** Ready for planning

<domain>
## Phase Boundary

Save currently confirmed songs locally so subscribers can revisit a durable Favorite Songs collection and manually use that list with any music service they prefer. This phase does not connect music-service accounts, match external catalogs, create playlists, or give saved songs playback authority.

</domain>

<decisions>
## Implementation Decisions

### Confirmed song eligibility

- **D-01:** A favorite-song candidate exists only at the action boundary when the shared listening model has a coordinator-confirmed channel, metadata availability is current, and separately trimmed semantic title and artist fields are both nonempty.
- **D-02:** Never create a song favorite from stale or unavailable metadata, a channel fallback, a display-composed string such as `Artist — Title`, skin-rendered text, browse selection, tune intent, or system Now Playing fallback fields.
- **D-03:** Album name is optional. Admit it only when `SiriusXMClient` exposes a verified, nonempty semantic album field from the observed provider contract. Never infer album name from artwork, source-channel context, macOS's album-title presentation slot, or other display text. Absence of album name must not block an otherwise eligible title-and-artist favorite.

### Durable song snapshot boundary

- **D-04:** Add a song-specific SwiftData record and projection behind the existing main-actor `LibraryStore`; do not reuse or overload channel `FavoriteRecord`.
- **D-05:** Persist only a fixed non-secret snapshot: original trimmed title and artist, normalized title-and-artist identity, optional verified album name, source-channel identity/presentation context, and saved date. Do not persist credentials, session material, stream resources, raw provider payloads, or durable artwork bytes/references in this phase.
- **D-06:** Deduplicate by normalized title and artist only. Album and source channel do not create separate identities for the same normalized song.
- **D-07:** Publish saved or removed state only after the durable mutation succeeds. A failed or fallback in-memory write must not make an ephemeral song appear saved, and it must not disturb playback.

### Favorite Songs collection and manual handoff

- **D-08:** Present Favorite Songs as a dedicated library collection distinct from channel Favorites. Song rows show title, artist, optional album when available, source-channel context, and saved date after relaunch.
- **D-09:** Favorite-song rows are not channels: they expose no Tune action, do not join playback queues, and do not imply current entitlement or playability.
- **D-10:** Each row provides keyboard- and VoiceOver-usable Copy and Remove actions. Copy writes `Artist — Title` using the saved trimmed presentation values; it does not invoke matching, lookup, authentication, or another service.

### Separate action and accessibility semantics

- **D-11:** Keep the existing compact-player star, `toggleFavorite`, and `compact.favorite` accessibility contract channel-only. Song saving uses a separately named **Favorite Current Song** action with its own saved/removed/disabled semantics.
- **D-12:** Route the song action through `ListeningSessionController` into `LibraryStore` as a desired durable state. It must not tune, change browse selection, interrupt audio, replace confirmed metadata, mutate system-media state, or create another playback/session owner.
- **D-13:** The action is disabled when D-01 eligibility is not satisfied and communicates why through app-owned accessible semantics; skins cannot provide or redefine its label, enabled state, result announcement, or persistence behavior.

### the agent's Discretion

- Choose the exact normalization algorithm and record/type names, provided normalization is deterministic for case, surrounding/internal whitespace, and Unicode-equivalent title/artist values while original trimmed presentation values remain available for display and copying.
- Choose whether **Favorite Current Song** appears in the Player menu, as a separate native compact-player control, or both. Any compact control must use the existing bounded app-owned semantic action/skin path rather than repurposing the channel star.
- Choose exact Favorite Songs tab placement, row layout, date formatting, search behavior, empty-state copy, confirmation behavior, and focus restoration while preserving the dedicated non-tunable collection and accessibility decisions above.
- Choose deterministic repeat-save and snapshot-refresh details provided one normalized title-and-artist identity remains, album stays optional, and no UI state publishes before durable success.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets

- `SiriusMac/Metadata/MetadataPresentationModel.swift` retains discrete current `programTitle` and `programArtist` alongside composed/stale/fallback presentation text; the discrete current fields are the eligibility seam.
- `SiriusMac/App/ListeningSessionController.swift` already owns confirmed playback projections, channel-favorite routing, durable-result announcements, and system-media publication.
- `SiriusMac/Library/LibraryStore.swift` provides the single main-actor SwiftData facade, fixed persisted-field allow-lists, save-before-publish behavior, rollback on save failure, and durable/in-memory-fallback distinction.
- `SiriusMac/Catalog/ListeningView.swift` provides the library tab/collection, search, row action, empty-state, keyboard, and VoiceOver patterns, though current rows are channel-shaped and must not be reused unchanged for songs.
- `Packages/SiriusXMClient/Sources/SiriusXMClient/Public/LiveListeningModels.swift` exposes semantic title, artist, and artwork; it is the correct public boundary for an optional verified album name.
- `Packages/SiriusXMClient/Sources/SiriusXMClient/InternalAdapters/LiveListeningAdapter.swift` currently observes title, artist, start timestamp, current-cut artwork, and an album-shaped object behind compatibility diagnostics; it does not yet expose a verified album-name field.

### Established Patterns

- Persist through one fixed non-secret model boundary, save successfully, then republish observable projections; never claim an ephemeral favorite is durable.
- Treat coordinator-confirmed playback and current semantic metadata as authority. Browse selection, tune intent, stale display retention, skins, and macOS fallback fields are presentation only.
- Keep channel favorites, recents, and song favorites as separate record/projection types with separate identity rules.
- Keep semantic actions and accessibility app-owned across Native and expressive appearances.
- App launch, app-hosted tests, `xcodebuild test`, UI automation, and live SiriusXM operations remain blocked without the repository's separate safety authorization.

### Integration Points

- Extend the internal metadata adapter and public `LiveProgramMetadata` only if a stable album-name field is verified; propagate it through `MetadataPresentationModel` without weakening current/stale/unavailable classification.
- Add the song record/projection and atomic mutation APIs to `LibraryStore`, including normalization, deduplication, durable reload, removal, and failure coverage.
- Add a confirmed-song candidate and desired-state route to `ListeningSessionController`, independent of channel-favorite and system-media mutations.
- Add the dedicated Favorite Songs collection plus Copy/Remove UI in the library, and add the distinct save action to an app-owned menu/control surface.
- Extend focused source/unit contracts for eligibility, stale/fallback rejection, normalization, album optionality, persistence failure, relaunch projection, separation from channel favorites, clipboard formatting, and accessibility labels/enabled state.

</code_context>

<specifics>
## Specific Ideas

- The durable list is intentionally a manual bridge to any service, not a partial playlist integration.
- Copy format is `Artist — Title`; album and source channel remain visible context rather than part of the copied lookup string.
- Album name enriches an entry only when the provider contract supplies a verified semantic value. Title and artist remain the durable identity and required minimum.

</specifics>
