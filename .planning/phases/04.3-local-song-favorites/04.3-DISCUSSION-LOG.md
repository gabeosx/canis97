## Corrections Made

### Durable Song Snapshot Boundary

- **Original assumption:** Persist title, artist, normalized title-and-artist identity, source-channel context, and saved date; no album field was included.
- **User correction:** Include an optional album name when SiriusXM supplies a verified, nonempty semantic album field. Title and artist remain required, and album does not participate in deduplication.
- **Reason:** SiriusXM's observed metadata has an album-shaped object and album-related artwork, so the user wants album name retained when it can be verified rather than guessed.

### Album evidence boundary

- The current adapter exposes title, artist, start timestamp, and current-cut artwork while observing an `album` object and `album.creativeArts` only in compatibility diagnostics.
- No stable album-name field is currently part of public `LiveProgramMetadata`.
- macOS Now Playing's album-title slot currently carries source-channel context and is not evidence of an actual album name.

## External Research

No external metadata schema was adopted. SiriusXM's public product pages do not provide a usable provider-contract definition, so the optional album decision remains gated on sanitized, compatibility-focused verification inside `SiriusXMClient`.
